# M1: Core engine

GOAL: A tested, offline comparison engine and CLI: load a suite and two runs, compare them case by
case with sound statistics, decide a verdict from a config, write Markdown + JSON reports, and exit
with a CI-friendly code. No adapters, no network, no LLM calls. See plans/ROADMAP.md.

SCOPE: `src/model_regression_detector/` (package; rename nothing), `tests/` (+ `tests/fixtures/`),
`examples/` (a tiny example suite, config and two runs), `pyproject.toml`/`uv.lock`, `README.md`,
`DECISIONS.md`, `CHANGELOG.md`.

DO NOT TOUCH: `plans/`, `AGENTS.md`, `CLAUDE.md`, `.github/` (unless a new test needs nothing extra
— then leave it). Never read `.env`. No network in tests.

STEPS:
1. **CLI name**: add a `mrd` console script (keep the long name as an alias).
2. **Formats** (pydantic v2 models, clear validation errors with file + line/case id):
   - Suite YAML: `name`, `metrics: [{name, kind: pass_fail|score, higher_is_better: true,
     weight?}]`, `cases: [{id, input, expected?, tags: []}]`. Unique ids.
   - Run JSONL: first line a header `{"type":"run","suite":..., "variant":..., "created_at":...,
     "meta":{model, prompt_version, git_sha, ...}}`, then one line per (case, repeat):
     `{"case_id", "repeat": 0, "output", "scores": {metric: bool|float}, "latency_ms"?, "cost_usd"?,
     "error"?}`. A case with `error` counts as failing every pass_fail metric and is listed.
   - Config TOML (`mrd.toml`): `alpha` (0.05), `min_effect` per metric (e.g. 0.05 absolute for rates),
     `bootstrap_samples` (10000), `seed`, `fail_on` (`regression` | `any_case_newly_failing`),
     per-tag overrides, `max_latency_regression_pct` (optional), `max_cost_regression_pct` (optional).
3. **Scorers** (`scorers.py`), used by later adapters and testable now: exact match (with
   normalisation options), numeric tolerance, regex, JSON field equality, set equality of row lists
   (order-sensitive or not), and a registry so adapters add their own. Pure functions.
4. **Comparison** (`compare.py`), paired on case id (cases missing from either run are reported
   and excluded; more than 10% missing → INCONCLUSIVE):
   - Repeats: per case, pass rate across repeats; a case is **flaky** if it both passes and fails
     within one run. Report flaky cases separately; for the binary test use the majority result.
   - pass_fail metrics: **McNemar exact test** (two-sided binomial on discordant pairs b, c),
     difference in pass rate with a 95% CI (paired bootstrap over cases, seeded).
   - score metrics: mean paired difference, paired bootstrap 95% CI, and a sign-flip permutation
     p-value (seeded).
   - Verdict per metric: REGRESSION if worse with p < alpha **and** |effect| ≥ min_effect;
     IMPROVEMENT symmetric; otherwise NO_CHANGE, or INCONCLUSIVE when n is too small to ever reach
     significance (e.g. fewer than 6 discordant pairs possible) — say why.
   - Overall verdict: REGRESSION if any metric regresses (or `fail_on` triggers), IMPROVEMENT if
     some improve and none regress, else NO_CHANGE / INCONCLUSIVE.
   - Slices: the same per tag (no multiple-testing magic; label slice results "exploratory" unless
     Holm-corrected — implement Holm across slices and say so).
   - Case lists: newly failing, newly passing, still failing, flaky; latency p50/p95 and total cost
     deltas when present.
5. **Reports** (`report.py`): Markdown suitable for a GitHub job summary/PR comment (verdict
   headline, metric table with CI and p, slice table, top newly-failing cases with expected vs
   output truncated and escaped for Markdown, flaky list, settings used); JSON with everything.
6. **CLI**: `mrd validate suite.yaml [run.jsonl...]`; `mrd compare --suite S --baseline B
   --candidate C [--config mrd.toml] [--md out.md] [--json out.json]`; exit codes: 0 PASS/NO_CHANGE/
   IMPROVEMENT, 1 REGRESSION, 2 INCONCLUSIVE (configurable: `--inconclusive-ok`), 3 usage/format
   error. `mrd report --json out.json` re-renders Markdown.
7. **Examples**: `examples/qa/` with a 40-case toy suite, a baseline run, a candidate with a real
   regression in one tag, and a candidate that differs only by noise (both generated by a small
   seeded script in `examples/make_runs.py`, committed outputs). README shows both comparisons.
8. **Tests**: format validation errors; scorers; McNemar against hand-computed values (e.g. b=10,
   c=2 → p≈0.0386); bootstrap CI coverage sanity (seeded); permutation test on a known case;
   repeats/flaky; missing cases → INCONCLUSIVE; Holm correction; verdict rules incl. min_effect;
   report rendering (golden file) and Markdown escaping of hostile outputs (`|`, backticks, HTML);
   CLI exit codes end-to-end on the examples.
9. Docs: README (what/why, quick start with the examples, how the statistics work in plain words,
   formats), DECISIONS (paired tests vs comparing averages, McNemar exact, bootstrap seed, Holm,
   no scipy if you can avoid it — or why you need it), CHANGELOG.

DONE WHEN:
- `uv run pytest && uv run ruff check .` pass offline.
- `uv run mrd compare` on the two example pairs gives REGRESSION (exit 1) and NO_CHANGE (exit 0).
- NOTES list the statistical choices and their tests.

ESTIMATE: 90–120 min.

REPORT: end with the report contract (CHANGED / EVIDENCE / ESTIMATE vs ACTUAL / NOTES / VERDICT).
Do not commit, do not push.
