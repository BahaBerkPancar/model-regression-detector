# M3: CI gate

GOAL: Make mrd usable as a pull-request gate: a reusable GitHub Action plus workflows that compare a
candidate run against a stored baseline, write the Markdown report to the job summary, and fail the
job on REGRESSION. Everything testable offline; nothing is pushed or run on GitHub during the build
(the repo has no remote yet).

SCOPE: `action.yml` (composite action at the repo root), `.github/workflows/` (this repo's own CI
plus a demo gate workflow), `src/model_regression_detector/` (baseline commands, GitHub helpers),
`docs/ci.md`, `examples/ci/` (ready-to-copy workflow for text-to-sql-guardrails), `tests/`,
README/DECISIONS/CHANGELOG.

DO NOT TOUCH: `plans/`, `AGENTS.md`, `CLAUDE.md`, the text-to-sql-guardrails repo (the t2s workflow
is written here as an example file only). Never read `.env`. No network, no LLM calls, no `gh`
commands that write.

STEPS:
1. **Baseline management**: `mrd baseline accept --run run.jsonl --to baselines/<suite>.jsonl`
   (copies + records provenance: git sha, variant, date, the run's verdict vs the previous baseline)
   and `mrd baseline show`. Refuse to accept a run whose header suite differs from the stored one.
2. **GitHub output helpers**: when `GITHUB_STEP_SUMMARY` is set, `mrd compare` appends the
   Markdown report there; when `GITHUB_OUTPUT` is set, writes `verdict=`, `exit_code=`,
   `regressed_metrics=` outputs. Emit `::error` / `::warning` annotations for REGRESSION /
   INCONCLUSIVE (escaped per GitHub's workflow-command rules — test hostile text with `%`, `\r`,
   `\n`, `::`). Size-cap the summary (GitHub's 1 MiB limit) with a truncation note.
3. **Composite action** `action.yml`: inputs `suite`, `baseline`, `candidate`, `config`,
   `inconclusive-ok` (default false), `python-version`; installs with `uv`, runs `mrd compare`,
   exposes the outputs. Pin third-party actions by full commit SHA (document how to update).
4. **Workflows**:
   - `.github/workflows/test.yml`: this repo's tests + ruff (core, without the t2s extra).
   - `.github/workflows/demo-gate.yml`: uses the local action (`uses: ./`) on the committed
     `examples/t2s` regression and noise runs as two matrix jobs; the regression job is expected to
     fail — use `continue-on-error` + a final step asserting the expected verdicts so the workflow
     itself is green while demonstrating the red gate.
   - `examples/ci/t2s-gate.yml`: the ready-to-copy workflow for t2s: on PRs touching `llm/`,
     `pipeline.py`, `config/`, prompts: start Postgres service, run `mrd run --adapter t2s` with a
     **recorded** generator by default (live model only behind a repository variable + secret and
     an explicit `MRD_ALLOW_SPEND=1`), compare against `baselines/t2s.jsonl`, comment-free (job
     summary only). Explain each permission (`contents: read` only).
5. **Validation offline**: a test that parses `action.yml` and both workflow files (YAML) and checks
   required keys, pinned SHAs, minimal permissions, and that every `run:` step quotes inputs safely
   (no `${{ inputs.* }}` interpolated directly into shell — pass via `env:`). If `actionlint` is
   installed locally use it, otherwise skip with a note (don't download it).
6. **Local dry run**: `scripts/ci_dry_run.sh` simulates the action steps with `GITHUB_STEP_SUMMARY`
   and `GITHUB_OUTPUT` pointing at temp files and shows the outputs for the two demo pairs.
7. **Docs**: `docs/ci.md` (how the gate works, baseline update flow, recorded vs live runs, cost
   safety, flaky handling with repeats), README section with a screenshot-like excerpt of the job
   summary (from the dry run), DECISIONS, CHANGELOG. Also from the M2 review: say plainly in
   DECISIONS that the noise demo's second seed was chosen for a clean 5/5 split, and make the pg
   equivalence test set up its own schema (call prepare_database) so it doesn't depend on test order.

DONE WHEN:
- `uv run pytest && uv run ruff check .` pass offline; `scripts/ci_dry_run.sh` shows REGRESSION /
  NO_CHANGE outputs and a written summary.
- Workflow/action validation tests pass; no unpinned third-party actions.

ESTIMATE: 60–90 min.

REPORT: end with the report contract (CHANGED / EVIDENCE / ESTIMATE vs ACTUAL / NOTES / VERDICT).
Do not commit, do not push.
